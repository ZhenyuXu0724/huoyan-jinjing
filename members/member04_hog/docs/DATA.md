## 标签和相对路径

类别 1–5 为 `M4x25`、`M5x10`、`M4x10`、`M4_hex_nut`、`flat_washer`；0 为 `non_catalogue`。固定数量暂用五类各 2。

- PASS：五类各 2，且目录外数量为 0。
- FAIL：任意目标类数量不符，或出现目录外件。
- 未经人工确认的规格不会因为程序计数通过就自动成为“已审核”。

`train.csv`、`valid.csv`、`test.csv` 只包含 `image_path,scene_id,label`，图片路径相对于清单所在目录。命令参数相对于仓库根目录；模块资源从代码文件位置定位。`provenance.json` 与 `test_provenance.json` 记录逐图计数、来源条件和划分。

## 程序能检查什么

下载时逐文件核验固定索引；旧统一 GT 的对象计数须与 `actual_counts` 一致。训练前检查跨分区场景 ID、文件身份与解码后灰度像素内容重复。验证预处理不随机；测试前检查冻结记录及权重、代码校验值，再检查与开发分区的重叠。

这些检查不能证明实物场景独立。当前 `scene_id` 使用 `UNVERIFIED:文件名`，仅用于明确标记尚未核实，不能当作真实摆放场景编号。相似连拍、不同光照下的同一摆放仍需成员 3 审核。

## 交接中尚未解决的问题

场景独立性、平垫圈规格、来源许可和最终人工标注复核待确认。旧 test 已公开，不具备封存资格；本轮只称“提供分区评测”。真实少件、多件、错规格等应单独报告支持数，不把目录外干扰验证的效果推广到所有错误类型。

收到真正独立的新数据后，由成员 3 按实物场景重建分区。新版本先训练和验证，再冻结，再评测；不根据当前 test 调整模型后沿用旧成绩。
